# LiDAR+GNSS 紧耦合里程计：观测建模与图优化

> 日期：2026-10-21 · 配套文档：《Lidar + GNSS 定位生产线》（spec）
> 本文回答两个问题：**每种观测如何构成因子图的 node/edge**；**图如何被优化**。
> 数学符号约定见文末附录 A。

## 1. 状态定义：图里有哪些 node

### 1.0 在 GLIM 三层结构中的位置

GLIM 本体的流水线是三层（`glim/include/glim/odometry/`、`mapping/sub_mapping.hpp`、`mapping/global_mapping*.hpp`）：

| 层 | 职责 | 本项目的处置 |
|---|---|---|
| **Odometry** | 帧级里程计（10Hz 主路径） | **一期交付物**——本文档 §1~§3 的全部内容都在这一层：现有 CT/IMU 前端之外新增紧耦合实现，IMU 预积分与 GNSS 因子进**内层**图 |
| **SubMapping** | 帧 → 子图聚合 | 一期不动、不启用 |
| **GlobalMapping** | 子图级位姿图优化，**回环在这一层**（子图间 scan matching 闭环 + 既有的 rtk_global 位置先验也挂在这层） | 一期不启用；二期可选项，见 §2.6 |

**湖州一期 = 只做 Odometry 层**（用户已拍板）。明确这一点的原因：里程计层不引入任何全局维护负担，回环的全局收益（见 §2.6）留作架构内生的二期升级路径。

### 1.1 坐标系

| 坐标系 | 含义 |
|---|---|
| ENU（world） | 东-北-天局部切平面，原点由首个 GNSS 因子 bootstrap（见 §3.4 gauge） |
| body | IMU 系（北云 INS 测量中心）。所有状态量都表达在 body 系上 |
| lidar | Seyond K2 雷达系。`T_lidar_imu` 外参**离线标定后锁定**（不进图——二期实证：平移在线估计与 INS 内部天线杆臂同构多模态，结构性不可观） |

### 1.2 节点（node）

每个**激光关键帧** k（10Hz）在图上立一组节点：

```
X(k) = (R_k, p_k) ∈ SE(3)     body 系在 ENU 下的位姿
V(k) ∈ R³                     body 系速度（ENU 下表达）
B(k) = (b_a, b_g) ∈ R⁶        IMU 加速度计/陀螺零偏（随机游走）
```

激光帧之间（100ms）的 IMU 样本（北云原始 IMU，~100Hz+）不单独立节点，全部预积分成一条边（§2.1）。

外参 `T_lidar_imu`、天线杆臂 `l_ant`（天线在 body 系的位置）是**常量参数**，不是节点。

## 2. 观测 → edge：每种观测怎么进图

### 2.1 IMU 预积分因子（边：k-1 → k，主骨架）

**原始观测模型**（北云 `/imu/data_raw`）：

```
ω̃(t) = ω(t) + b_g(t) + n_g(t)      陀螺：真值 + 零偏 + 白噪
ã(t) = a(t) + b_a(t) + n_a(t)      加速度计：同上
```

**预积分**（Forster 标准式）：把 k-1 到 k 之间的全部 IMU 样本积成三个相对量，使它们**不依赖初值**，零偏修正通过一阶雅可比事后注入：

```
ΔR_ik = ∏ Exp((ω̃(t) − b_g) Δt)                      相对旋转
Δv_ik = Σ ΔR_it (ã(t) − b_a) Δt                     相对速度增量
Δp_ik = Σ [Δv_it Δt + ½ ΔR_it (ã(t) − b_a) Δt²]     相对位移增量
```

**残差**（连接 (X,V,B)_{k-1} 与 (X,V,B)_k，即一条 5 元边）：

```
r_R = Log( ΔR_ikᵀ · R_{k-1}ᵀ R_k )
r_v = R_{k-1}ᵀ (V_k − V_{k-1} − g·Δt) − Δv_ik
r_p = R_{k-1}ᵀ (p_k − p_{k-1} − V_{k-1}Δt − ½gΔt²) − Δp_ik
```

噪声：预积分协方差随样本数递推传播（GTSAM `PreintegratedImuMeasurements` 内置）。零偏随机游走单独一条边：`r_b = B_k − B_{k-1}`，σ 由 Allan 方差标定。

**这条边是"无状态机"的核心**：GNSS 消失时它独自维持递推（替代 flofix_loc 的 coast/DR 桥接补丁）；GNSS 在时它与 GNSS 因子按各自协方差自然博弈，没有任何代码"决定"谁说了算。

### 2.2 激光 between 因子（边：k-1 → k）

**观测**：KISS scan-to-scan 配准。当前帧点云 deskew 后（deskew 用 §2.1 的 IMU 传播位姿，替代 KISS 原版的匀速模型）与上一帧配准，输出相对位姿：

```
z_kiss = T_{k-1,k} ∈ SE(3)      附带配准收敛协方差 Σ_kiss
```

**残差**（二元边 X_{k-1} ↔ X_k）：

```
r_lidar = Log( z_kiss⁻¹ · (X_{k-1}⁻¹ X_k) )
```

**噪声自适应**：KISS 的 σ 不取常数——退化场景（长廊、开阔地）配准协方差自动放大（按特征值/适应度映射），等效于 flofix_loc "弱观测降权"，但无需离散闸门。

### 2.3 GNSS 位置因子（一元边：X_k）

**观测**：北云原始 RTK 定位（**不是** INSPVA 融合位置——融合位置已被 INS 内部杆臂配置"预消化"，与本图的外参同构，二期实证这是外参在线估计多模态的根因）。板卡同时上报 σ_enu 与质量档。

**观测模型**：天线相位中心在 ENU 下的位置 = body 位置 + 旋转后的杆臂：

```
z_gnss = p_k + R_k · l_ant + n_gnss
```

**残差**（一元边，只挂 X_k）：

```
r_gnss = z_gnss − (p_k + R_k · l_ant)
```

**定权**——这是"不区分 GNSS 状态"的具体实现：

```
Σ_gnss = diag( max(σ_board, σ_floor)² )      σ_floor = 系统误差量级（~米级）
```

- FIX：板卡 σ ≈ 2cm → 强约束，图被锚到绝对坐标
- FLOAT：板卡 σ ≈ 20–50cm → 弱约束，只纠慢漂不抢主权
- 单点/失锁：σ 极大或观测缺席 → 因子自然失效，IMU+激光递推

**没有任何 if(rtk_status==4) 的分支**。质量差不是"换个模式"，只是 σ 变了。再外套 Huber 鲁棒核（§3.2），假 FIX 跑飞这类野值被核函数压制——fix#10/13 的锁存闸门由连续数学替代。

### 2.4 零速因子（可选边：V_k，静止段）

检测到静止（IMU 加速度/角速度幅值 + RTK speed 多条件，规则复用 gnss_bringup metrics 的零速判定）时加：

```
r_zupt_v = V_k                    σ 极小
r_zupt_w = π_yaw 相关项           抑制静止漂移
```

对应 flofix_loc 的"静止冻结"行为，但同样无状态：车一动约束自动消失（检测条件不再满足）。

### 2.5 先验因子（一元边：首帧）

`X(0)`、`V(0)`、`B(0)` 各一条 PriorFactor，σ 宽松——只为图可解，不注入信息。`B(0)` 的收敛靠在线估计（预积分边 + 其余观测）。

### 2.6 回环因子（二期可选项，一期不启用）

回环在本架构里**不是新机制，只是又一条边**——这是因子图框架相对滤波/递推架构的结构性优势。但它的落点不在 Odometry 层的帧级图，而在 **GlobalMapping 层的子图位姿图**：

```
节点：S_i = 第 i 个子图的位姿（聚合了数十个帧级节点）
边 1：相邻子图 between（由 Odometry 链汇总而来）
边 2：回环边 S_i ↔ S_j（i、j 相隔很远，车回到同一地点）：
     z_loop = 子图间 scan matching 给出的相对位姿
     r_loop = Log( z_loop⁻¹ · (S_i⁻¹ S_j) )
边 3：GNSS 位置先验（既有 rtk_global 模块已挂在这层）
```

**收益**：里程计（§2.1~2.5 的帧级图）只能让漂移"增长得慢"，回环边一进图，iSAM2 把约束信息沿 Bayes tree 回传，**整段轨迹的累积漂移被摊薄乃至事后归零**。对湖州这种棚内外固定路线往复的场景，回环几乎必然存在，收益是实在的而非理论的。

**代价与纪律**：①误检风险——一条错回环比没有回环更糟，必须几何验证 + 鲁棒核；②全局优化打破固定滞后的实时性预算——回环只跑后端异步线程，永不进 10Hz 主路径；③一期不启用：湖州一期交付 Odometry 层，本节仅为说明架构的升级路径已内生存在。

## 3. 图怎么被优化

### 3.1 求解器：iSAM2 增量优化

每个激光帧到达 → 新增一组节点 + §2 的若干边 → iSAM2 只重线性化受影响子树（Bayes tree 局部更新），不重解全图。原型（tck_calib_v2）是批量 LM 离线验证数学正确性；产品化改 iSAM2 是在线性的来源。**验收锚点**：同一 bag 上 iSAM2 版对批量版 ATE 差必须 < 1cm（确定性平台），证明增量化没丢精度。

### 3.2 鲁棒核与定权纪律

GNSS 因子外套 Huber 核：残差小于 δ 时二次（信息全收），大于 δ 时线性（梯度封顶）：

```
ρ(r) = ½ r²          |r| ≤ δ
ρ(r) = δ|r| − ½ δ²   |r| > δ            δ ≈ 1.345·σ
```

**σ_floor 纪律**（一期实证规则）：floor 必须留在**残余系统误差量级**（米级），不能压到板卡标称 cm 级——地图倾斜/gauge 残差等系统误差 ~1–4m 是真实存在的，floor 低于它，优化器会把"好解"强行拖向含系统误差的观测（实证：floor=5cm 时 ATE 从 0.32 恶化到 4.0）。

### 3.3 实时性保障

- **滑窗边缘化**：图只保留最近 N 个关键帧（⚠️ N 与 Orin 算力预算一起在 plan 阶段实测定），旧节点边缘化为先验——全局一致性让位给实时性，绝对精度由在场 GNSS 因子维持
- **IMU 传播输出**：优化以 10Hz 跑，对外发布用最新优化结果 + IMU 传播到当前时刻（≥100Hz），替代 flofix_loc 的 RateLifter（vcu+wz 运动学外推）
- **线程模型**（沿用 flofix fix#1 教训）：回调线程 / 优化线程 / 发布线程三线程；优化卡顿时 IMU 传播保底不停发，staleness 用墙钟判

### 3.4 gauge：ENU 原点的出生证明

GNSS 是绝对观测，图不存在 gauge 自由度问题——但**原点选择影响数值**。规则（沿用 GaugeRegistry 教训）：首个 σ 达标的 GNSS 观测冻结 ENU 原点，此后不变；原点约定显式记录（日志可复算）。低质量样本（FLOAT 游走）不得参与 bootstrap（aligner_min_quality 门）。

### 3.5 时间对齐

紧耦合对时标敏感（±0.05s 时标误差 = 0.3m 级残差，既有实证）：三路传感器的 PTP 时标统一到同一时钟域；GNSS 观测时间戳与激光节点时间**插值对齐**而非就近取整。.pos 后处理数据有 GPST/UTC 两种时基（差 18s），必须走 gnss_core pos_io 的头部识别，不许手写解析。

### 3.6 健康度 → is_valid（无状态机的可用性表达）

不输出"第几阶段"，输出连续健康度：

| 指标 | 来源 | 含义 |
|---|---|---|
| 位姿协方差 trace | iSAM2 marginal | 当前估计的绝对不确定度 |
| GNSS 新息 χ² | r_gnssᵀ Σ⁻¹ r_gnss | GNSS 与图的一致性（假 FIX 检测） |
| 前端配准质量 | KISS fitness/特征值 | 激光退化检测 |

`is_valid` = 三指标联合门限（具体阈值 plan 阶段定）。诊断直接回答"是前端退化、IMU 异常还是 GNSS 新息异常"。

## 4. 这套图为什么值 0.100m

既有实证数字链：调好 KISS 纯前端 0.57m → 松耦合 iSAM2（外层固定滞后）0.155m → **本架构（内层紧耦合）0.100m**。差距来源正是 §2 的结构：松耦合把 GNSS 钉在"前端已经定死的位姿"上，前端误差进了先验就锁死；本架构 GNSS/IMU/激光三方在**同一张图**里同时博弈，前端的慢漂被 GNSS 实时纠正、GNSS 的粗跳被 IMU/激光一致性压制。
